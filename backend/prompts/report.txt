## Special Formatting Rules

### Object Normalization

Many extracted ESG values may appear in the following format:

{
  "status": "...",
  "value": "..."
}

These objects are acceptable ONLY for fields explicitly defined in the target schema
(e.g. scope1, scope2, scope3).

For every other section:

- Never place JSON objects inside arrays such as:
  - findings
  - recommendations
  - executiveSummary
  - policies

Instead convert them into plain human-readable strings.

Examples:
Dont take same values, missing questions should be collected and framed human-readable strings.


Input

{{
  "status": "Verified",
  "value": "Independent verification conducted by TÜV Rheinland. dont take same data"
}}

Output

"Verified: Independent verification conducted by TÜV Rheinland."

--------------------------------

Input

{{
  "status": "Partially Implemented",
  "value": "Supplier sustainability assessments are ongoing."
}}

Output

"Partially Implemented: Supplier sustainability assessments are ongoing."

Never output JSON objects inside findings or recommendations.

Correct

"findings": [
    "Independent verification conducted by TÜV Rheinland.",
    "91% of waste was recycled."
]

Incorrect

"findings": [
    {
        "status":"",
        "value":"Independent verification conducted by TÜV Rheinland."
    }
]

The final JSON must contain only plain text strings inside arrays.

## Transformation Rules

- Extract company information into the company section.
- Generate a concise executiveSummary using the available ESG information.
- Move utility bill data into the environment section (including monthlyElectricityConsumption, monthlyNaturalGasConsumption, and monthlyWaterConsumption arrays if available).
- Move HR and health/safety/incident information into the social section:
  - Count all logged entries/rows in any Incident Register, Human Rights Incident Register (e.g. HR-2026-001 through HR-2026-004 = 4 incidents), or Health & Safety Register, and set social.incidents to this total numeric integer (e.g., 4).
  - If no incidents are logged or reported, set social.incidents to 0.
- Move governance and compliance policies into the governance section.
- Convert ESG observations into findings.
- Convert improvement actions into recommendations.
- Preserve numeric precision.
- Preserve original units.
- Remove duplicate values.
- Use null for missing values.
- Ensure findings and recommendations contain ONLY human-readable strings.
- Only scope1, scope2, and scope3 may contain {status, value} objects.
